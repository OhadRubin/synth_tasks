\begin{center}
    \textbf{Compositional Difficulty}
\end{center}

\paragraph{1. Task and machine.}
Let $\Sigma$ be an alphabet. A task instance is
\[
\tau=(x,Y_x),\qquad x\in\Sigma^*,\qquad Y_x\subseteq\Sigma^*,
\]
where $x$ is the minimal immutable problem specification and $Y_x$
is the family of acceptable answers. Correctness is relational:
\[
\operatorname{correct}(y,x)\iff y\in Y_x.
\]
The machine is parameterized by $\theta$ and produces answers according to
$M_\theta(y\mid x,c)$, where $c$ contains all auxiliary context.
The correspondence with a Turing machine is: $x$ is the read-only input
tape, $c$ is the work tape, $\theta$ is the program, and $Y_x$ specifies
accepting outputs.

\paragraph{2. Context transformations.}
Initially $c_0$ is empty unless auxiliary information is supplied.
An append-only context update has the form
\[
c_i=c_{i-1}\oplus z_i,
\]
where $\oplus$ denotes concatenation. The update $z_i$ may contain an
intermediate deduction, retrieved fact, tool result, partial calculation,
subgoal, previous answer, or observation. Retrieval context and
chain-of-thought steps therefore have the same formal status: both are
information written into $c$.

Fix a class $\Phi$ of admissible primitive transformations
\[
\phi:(x,c)\mapsto(x,c'),\qquad c'=\phi(x,c).
\]
A depth-$d$ computation is a trace
\[
\pi:\quad
c_0\xrightarrow{\phi_1}c_1
\xrightarrow{\phi_2}\cdots
\xrightarrow{\phi_d}c_d,
\qquad \phi_i\in\Phi,
\]
followed by an answer sampled or decoded from
$M_\theta(\cdot\mid x,c_d)$.

A machine realization uses a context-generating transition $U_\theta$
and a halting/output operation $H_\theta$:
\[
c_{t+1}=c_t\oplus U_\theta(x,c_t),
\qquad
y=H_\theta(x,c_d).
\]
The computation is repeated composition of the context update.

\paragraph{3. Compositional depth.}
For error tolerance $\epsilon$, define
\[
D_\epsilon(x;\theta,\Phi)
=
\min\left\{
d:
\begin{array}{l}
\exists\,\phi_1,\ldots,\phi_d\in\Phi,\quad
c_i=\phi_i(x,c_{i-1}),\\
M_\theta(Y_x\mid x,c_d)\geq 1-\epsilon
\end{array}
\right\}.
\]
Here $M_\theta(Y_x\mid x,c_d)$ is the total probability of an acceptable
answer. Depth is the minimum number of primitive compositions needed
to make an answer recoverable with the specified reliability.

At the task level, let $T:x\mapsto Y_x$ and fix a primitive task class
$\mathcal P$. A realization is a composition of smaller tasks:
\[
T=T_d\circ\cdots\circ T_1,\qquad T_i\in\mathcal P.
\]
Its minimum depth is
\[
D_{\mathcal P}(T)
=
\min\left\{
d:T=T_d\circ\cdots\circ T_1,\quad T_i\in\mathcal P
\right\}.
\]
This is depth relative to a basis, as in circuit complexity. If arbitrary
functions are allowed as primitives, every task can be assigned depth one.
The primitive class must therefore be fixed before comparing depths.

Two scales should be distinguished:
\[
\begin{aligned}
d_{\mathrm{machine}}
&=\text{number of primitive machine transitions},\\
d_{\mathrm{comp}}
&=\text{number of dependent subtasks}.
\end{aligned}
\]
A subtask may require many machine transitions. For an autoregressive
model, machine transitions might correspond to token-generation steps;
compositional depth instead counts stages such as
$x\xrightarrow{T_1}z_1\xrightarrow{T_2}z_2\xrightarrow{T_3}y$.

\paragraph{4. Work space.}
For a trace $\pi$, the context-space usage is
\[
S(\pi)=\max_{0\leq i\leq d}|c_i|.
\]
Let $\Pi_\epsilon(x;\theta,\Phi)$ denote the admissible traces satisfying
the success condition above. Minimum work-space requirement is
\[
S_\epsilon(x;\theta,\Phi)
=
\min_{\pi\in\Pi_\epsilon(x;\theta,\Phi)}
\max_{0\leq i\leq|\pi|}|c_i|.
\]
If irrelevant context can be discarded, the corresponding live-space
measure is
\[
S_{\epsilon,\mathrm{live}}(x;\theta,\Phi)
=
\min_{\pi\in\Pi_\epsilon(x;\theta,\Phi)}
\max_i|\operatorname{live}(c_i)|,
\]
where $\operatorname{live}(c_i)$ is the information that must remain
available for later steps. Depth and space measure, respectively,
sequential composition and maintained working context.

\paragraph{5. Retrieval and prior examples.}
Retrieval is a context update $c_{i+1}=c_i\oplus r_i$.
If the origin of an update matters, label each transition by
\[
\kappa_i\in
\{\text{internal},\text{retrieval},\text{tool},\text{observation}\}.
\]
The resulting typed trace allows quantities such as
\[
D_R(\pi)=\#\{i:\kappa_i=\text{retrieval}\}
\]
without changing the underlying computation model.

Previously seen examples $X$ enter in either of two places.
Training examples are summarized by
$\theta=\operatorname{Learn}(X)$.
Examples available during inference are included in $c_0$.
Thus prior experience is represented through $\theta$ or $c$.

\paragraph{6. Noise and robust depth.}
Let perturbation channels act on the input and work context:
\[
\widetilde{x}\sim N_{x,\eta}(x),
\qquad
\widetilde{c}_i\sim N_{c,\eta}(c_i),
\]
where $\eta$ specifies the noise magnitude or distribution.
Define robust depth by applying the same success criterion to
computations using the perturbed input and context:
\[
D_{\epsilon,\eta}(x;\theta,\Phi)
=
\min\left\{
d:
\begin{array}{l}
\exists\text{ an admissible depth-}d\text{ computation},\\
\Pr_{\theta,\eta}(\widehat y\in Y_x)\geq1-\epsilon
\end{array}
\right\}.
\]
Probability is over the perturbations and machine output; correctness
is measured against the original answer family $Y_x$.
Nominal depth is $D_{\epsilon,0}$, and
\[
D_{\epsilon,\eta}-D_{\epsilon,0}
\]
can be interpreted as fragility under the specified noise.

\paragraph{7. Answer-family uncertainty.}
Having $|Y_x|>1$ need not make a task difficult: several answers may
be valid. Input perturbations can instead change which answers are valid,
from $Y_x$ to $Y_{\widetilde{x}}$. For a distance $\operatorname{dist}$
between answer sets, define
\[
U_\eta(x)
=
\mathbb E_{\widetilde{x}\sim N_{x,\eta}(x)}
\left[
\operatorname{dist}(Y_x,Y_{\widetilde{x}})
\right].
\]
This measures sensitivity of the answer relation to perturbations,
separately from computational depth and space.

\paragraph{8. Interpretation.}
Instance difficulty is the minimum depth and space of a successful
context-generating computation, relative to $\theta$ and a fixed
primitive basis $\Phi$; robustness describes its behavior under noise.
Reasoning chains contribute composition depth. Interacting constraints
can increase space and depth. Distractors can increase search, and
lexical complexity can require transformations before useful state is
constructed. Rare knowledge may require a retrieval transition.
Context length bounds the live information available but does not by
itself determine difficulty. Ambiguity concerns the answer relation
and its sensitivity rather than an additional computational resource.

\paragraph{9. Task families and composition.}
A task family $\mathcal F_j$, one of
$\mathcal F=\{\mathcal F_1,\ldots,\mathcal F_m\}$, assigns to each
structural parameter $k$ a set $\mathcal F_j(k)$ of component tasks.
Depending on the family, $k$ may specify the number of constraints,
dependency depth, or amount of state.

Every task in $\mathcal F_j(k)$ is a relation with the signature
\[
T:A_j^1(k)\times\cdots\times A_j^{m_j}(k)\longrightarrow 2^{B_j(k)},
\]
where $T(u)$ is the set of acceptable outputs for the input tuple $u$.
Every such $T$ is total: $T(u)\neq\emptyset$ for every input tuple $u$. A
family whose natural relation is partial restricts its input types to the
inputs where it is defined.

Components are composed along a directed acyclic graph (DAG) $G$. Each
node $v$ is either a leaf, which holds an input value of some type, or a
component node, which holds a task $T_v\in\mathcal F_{j_v}(k_v)$ and has
type $B_{j_v}(k_v)$. The $i$-th input of a component node is an edge from
another node whose type is contained in $A_{j_v}^i(k_v)$, and the edges
form no cycle. A value may be read by several nodes. One node, the sink,
holds the answer. An assignment gives every node $v$ a value $z_v$ such
that each component node satisfies
\[
z_v\in T_v(z_{v_1},\ldots,z_{v_m}),
\]
where $v_1,\ldots,v_m$ are its inputs. With the leaf values fixed, the
acceptable answers are the sink values of all assignments, and totality
guarantees that at least one assignment exists. A chain is the special
case in which every component has one input and every value has one
reader. There the definition reduces to
\[
(T_2\circ T_1)(u)
=
\bigcup_{z\in T_1(u)}T_2(z):
\]
an output is acceptable if it can be reached through an acceptable
intermediate output. A component that is itself a DAG can be inlined into
the outer DAG, so composition stays within DAGs.

\paragraph{10. Composed instances.}
A composed instance consists of a DAG $G$ as in paragraph 9, its
component tasks $(T_v)_v$, and the values $(z_v)_{v\ \mathrm{leaf}}$ at
its leaves. Its problem statement and answers are
\[
x=\operatorname{Encode}\big(G,(T_v)_v,(z_v)_{v\ \mathrm{leaf}}\big),
\qquad
Y_x=\{z_{\mathrm{sink}}: z\text{ is an assignment}\},
\]
where $\operatorname{Encode}$ produces a problem statement containing the
information needed to specify the task.

The structure is read backward from the answer, and the values are
computed forward from the inputs. Read backward, the nodes with a path to
the sink are the ones that determine $Y_x$, and every edge satisfies the
type condition of paragraph 9, so the components are compatible by
definition. Other nodes do not affect $Y_x$; included in $x$, they act as
distractors (paragraph 8). Read forward, an evaluation order of $G$, in
which every node comes after its inputs, computes an assignment one node
at a time, $z_v\in T_v(z_{v_1},\ldots,z_{v_m})$, and totality guarantees
that every step has a value to choose. These values are intermediate
results that can be recorded in $c$. Some or all of this context may be
supplied to the solver, or the solver may be required to construct it.

When every value has exactly one reader, the DAG is a tree rooted at the
answer: a derivation in a grammar whose nonterminals are types and whose
rules are component signatures. COGS builds a compositional benchmark from
such derivations, using a probabilistic context-free
grammar.\footnote{Najoung Kim and Tal Linzen.
\emph{COGS: A Compositional Generalization Challenge Based on Semantic
Interpretation}. Proceedings of EMNLP, 2020, pp.\ 9087--9105.}

\paragraph{11. Composition structure and solving difficulty.}
The structure of a composed instance need not be the shortest way to
solve it. For example, for an invertible function $f$,
\[
T=f^{-1}\circ f
\]
contains two components but reduces to the identity.

Let $T$ be the task computed by the DAG. If each component node $v$ has a
realization of depth at most $\delta_v$ in the fixed primitive basis
$\mathcal P$, evaluating the nodes with a path to the sink in an
evaluation order establishes
\[
D_{\mathcal P}(T)\leq\sum_v\delta_v,
\]
with the sum over those nodes. The number of component nodes on the longest path from a
leaf to the sink bounds the number of dependent subtasks
$d_{\mathrm{comp}}$, and the largest number of values computed but still
to be read at any point of an evaluation order bounds the values that
must be held between components.

The structure can also overstate difficulty relative to $\theta$.
Components that map many inputs to one output make the answer nearly
constant across instances that share a structure. A machine whose
$\theta$ was learned from such instances (paragraph 5) can output that
answer without computing, so $D_\epsilon$ can be $0$.

A composed instance is therefore described by the triple
\[
\boxed{(x,Y_x,\gamma),}
\]
where $\gamma$ records the DAG, an evaluation order, and the component
tasks. Its structure is explicit, while the relationship between that
structure and minimum solving difficulty remains to be established.

\paragraph{12. Budgeted machines.}
In paragraph 3 the trace is chosen freely from $\Phi$ and $\theta$ enters
only in the final readout, so $D_\epsilon$ counts steps written by
someone other than the solver. A budgeted machine generates its own
trace and has three separately bounded stores: its parameters, its
initial context, and its working context. The context at step $t$ is
\[
c_t=c_0\oplus w_t,
\qquad
w_{t+1}\sim W_\theta(\cdot\mid x,c_t),
\qquad
y\sim M_\theta(\cdot\mid x,c_d),
\]
where $c_0$ is supplied and read-only, $w_0$ is empty, and the
transition $W_\theta$ outputs the whole new working part, so it may keep,
rewrite, or discard earlier content. The append-only machine of
paragraph 2 is the case $w_{t+1}=w_t\oplus z_{t+1}$. With all sizes
measured in bits, the budgets are
\[
|\theta|\leq B_\theta,
\qquad
|c_0|\leq B_0,
\qquad
|w_t|\leq B_c\ \text{for all }t.
\]
The three stores are paid for differently. The parameters are computed
once per family, by training (paragraph 5), and reused on every
instance. The initial context is filled per instance by a supplier, at
no cost to the solver. The working context is written per instance by
the solver, one transition per update. A combined budget would let
content move to the cheapest store, so each store has its own.

\paragraph{13. Budgeted depth.}
Scaling is a statement about growing instances, so budgeted depth is
defined on a sequence $(\mathcal D_n)_n$ of distributions over
instances, where $n$ is a size such as the number of component nodes of
a composed instance (paragraph 10). A supplier is a map
$\sigma:x\mapsto c_0$. Context that is the same for every instance of
$\mathcal D_n$, such as fixed in-context examples, is part of $\theta$,
so $\sigma$ supplies only what depends on $x$. Budgeted depth is
\[
D_\epsilon(n;B_\theta,B_0,B_c)
=
\min\left\{
d:
\begin{array}{l}
\exists\,\theta,\ |\theta|\leq B_\theta,\quad
\exists\,\sigma,\ |\sigma(x)|\leq B_0,\\
\Pr\big(y\in Y_x\big)\geq1-\epsilon
\end{array}
\right\},
\]
where $W_\theta$ outputs only strings of at most $B_c$ bits, and the
probability is over $x\sim\mathcal D_n$, the trace $w_1,\ldots,w_d$
generated from $c_0=\sigma(x)$, and the answer $y$. One $\theta$ serves
every instance of $\mathcal D_n$. A scaling statement fixes the budgets,
or lets them grow at a stated rate, and describes $D_\epsilon$ as $n$
grows.

\paragraph{14. What each budget excludes.}
$B_\theta$ and $B_0$ each close a way of making $D_\epsilon$ trivial;
$B_c$ adds working space as a second resource.

Without $B_\theta$, $\theta$ can store a table from the instances of
$\mathcal D_n$ to their answers and answer at depth $0$. The table grows
with the support of $\mathcal D_n$, so with $B_\theta$ fixed it
eventually stops fitting and the answers must be computed by
transitions. Answers that are nearly constant across $\mathcal D_n$
(paragraph 11) need no table and stay cheap under every $B_\theta$. When
$\theta$ parameterizes a fixed architecture, $B_\theta$ also bounds the
network that computes one transition, which takes the place of the
class $\Phi$ of paragraph 3. A component that is the same across
$\mathcal D_n$ and absent from $x$ must be stored in $\theta$ or supplied
in $c_0$; this is the retrieval of rare knowledge in paragraph 8.

Without $B_0$, $\sigma$ can place every intermediate value $z_v$ of a
composed instance, or the answer itself, in $c_0$, and $D_\epsilon$
drops to $0$. If each value takes $b$ bits, $c_0$ holds at most
$\lfloor B_0/b\rfloor$ of them, and $B_0=0$ requires the solver to
construct every intermediate result itself (paragraph 10).

With the append-only transition of paragraph 2 and nonempty updates,
$|w_t|\geq t$, so no trace runs longer than $B_c$ steps and $B_c$ acts
as a cap on depth. When $W_\theta$ may discard, $B_c$ bounds the values
held between components, which is the live space of paragraph 4, and
depth and working space can trade off against each other.

\paragraph{15. External memory.}
A tool-calling agent can offload information to a file $F$ of unbounded
capacity. The machine state at step $t$ is then $(w_t,F_t)$, and each
transition is either an update of $w_t$ as in paragraph 12 or a tool
call ($\kappa=\text{tool}$, paragraph 5). A tool call copies a string of
at most $B_c$ bits between $w_t$ and $F_t$, at an address named in
$w_t$, and counts as one transition. When $x$ itself exceeds what one
transition can read, it starts in the file, $F_0=x$, and transitions see
it only through reads. Anything else in the file at the start belongs to
one of the existing budgets: content that depends on $x$ counts toward
$B_0$, and content kept from earlier instances of $\mathcal D_n$ counts
toward $B_\theta$. A file kept across instances without this accounting
could hold the answer table excluded in paragraph 14.

The file removes $B_c$ as a limit on instance size. To evaluate a
composed instance, the agent visits the nodes in an evaluation order,
reads the inputs of the current node from the file, computes its value,
and writes it back. The working context then holds one component at a
time: its inputs, its output, its internal working space, and an address
of $O(\log n)$ bits. An append-only agent gains the same reach if it may
clear its working context after writing to the file.

Instance size is instead paid for in transitions. Without the file,
every value still to be read must sit in the working context, so $B_c$
decides which instances are solvable at all. With the file, a value that
leaves the working context and is read back later costs tool
transitions, and the depth of a trace counts these transfers alongside
the component evaluations. When values cannot be obtained by a shortcut,
for instance when components are random functions over large domains,
the minimum number of transfers for evaluating $G$ is the cost of the
red--blue pebble game of Hong and Kung.\footnote{Jia-Wei Hong and
H.~T.~Kung. \emph{I/O Complexity: The Red-Blue Pebble Game}. Proceedings
of STOC, 1981, pp.\ 326--333.} A red pebble marks a value in the working
context and a blue pebble a value in the file; a node can be computed
only when its inputs carry red pebbles, at most $\lfloor B_c/b\rfloor$
red pebbles are available, and each change of color is one transfer. A
chain needs no transfers for its intermediate values, since each value
is read right after it is computed. Transfers arise when the values
computed but still to be read (paragraph 11) outnumber the red pebbles,
so their number grows with the width and sharing of $G$.

This paragraph covers tools that store and retrieve. A tool that returns
the result of a computation, such as an interpreter, is a transition
whose power lies outside $\theta$; without a budget of its own, it plays
the role of the unrestricted $\Phi$ of paragraph 3.

\paragraph{16. Offloading as a task.}
The tool calls of paragraph 15 copy strings exactly, but choosing what to
write, under which key, and how to find it again is computation the
agent performs. Offloading therefore adds two task families in the sense
of paragraph 9. Let $\mathbb F$ be the set of file contents, $V$ the set
of values, and $Q$ the set of queries, where a query is what the agent
knows about a value it will need: an exact address, or a description
from which the entry must be found. The two families have the signatures
\[
T_{\mathrm{store}}:\mathbb F\times Q\times V\longrightarrow 2^{\mathbb F},
\qquad
T_{\mathrm{ret}}:\mathbb F\times Q\longrightarrow 2^{V}.
\]
State maintenance, $T_{\mathrm{store}}(F,q,z)$, accepts every file from
which $z$ can be recovered with the query $q$ and every entry still to
be read can be recovered with its own query. Retrieval,
$T_{\mathrm{ret}}(F,q)$, accepts the value recorded for $q$. The
acceptable outputs of maintenance are thus defined through the
retrievals that follow. The structural parameters of both families are
the number of entries in the file, which act as distractors
(paragraph 8); the number of stale entries, which hold values that later
steps have replaced; and how directly $q$ identifies its entry, from an
exact address, which makes retrieval a lookup, to a description, which
makes it a search. The layout the agent chooses when storing sets these
parameters for every later retrieval, so work at write time trades
against work at read time.

An offloading strategy, a red--blue pebbling of $G$ (paragraph 15),
turns the main instance into a larger composed instance $G^F$. Each
write of $z_u$ becomes a store node, and each later read of $z_u$ by a
node $v$ becomes a retrieval node, so an edge that passes through the
file becomes
\[
u\xrightarrow{\;z_u\;}T_{\mathrm{store}}
\xrightarrow{\;F_s\;}\cdots\xrightarrow{\;F_r\;}
T_{\mathrm{ret}}\xrightarrow{\;z_u\;}v,
\]
where $s$ and $r$ are the steps of the write and the read. The file
contents pass through every store node in order, forming a chain that
is the state the agent maintains. The components of $G^F$ are those of
$G$ together with the induced store and retrieval instances, whose
parameters the strategy fixes: how many entries are live at each read,
how many have gone stale, and how long each entry waits between its
write and its read. Lowering $B_c$ moves more values into the file and
enlarges these instances, so the transfers of paragraph 15 are paid for
twice, in transitions and in the difficulty of each read.

The augmented instance gives a check on whether the agent can solve the
main task with the file at a working budget $B_c$. If each node $v$ of
$G^F$ is solved with error at most $\epsilon_v$, then by the union bound
every node is correct with probability at least $1-\sum_v\epsilon_v$,
and the sink then holds an acceptable answer. Store and retrieval can be
measured as standalone tasks at the parameters a strategy induces. The
main task is solvable at budget $B_c$ if some strategy induces store and
retrieval instances that, together with the components of $G$, the
agent solves reliably. An agent that fails retrieval at the parameters a
strategy needs cannot rely on that strategy and must use one that keeps
fewer entries live, at the cost of more working context or more
recomputation.

\paragraph{17. Compaction.}
Agents in practice keep an append-only context and, when it fills,
compact it: they summarize it into a short context and continue from
there. This is the append-only machine of paragraph 2 with $B_0$ and
$B_c$ bounding a single iteration and any number of iterations allowed.
Iteration $\ell$ runs
\[
c^{(\ell)}_t=c^{(\ell)}_0\oplus w^{(\ell)}_t,
\qquad
w^{(\ell)}_{t+1}=w^{(\ell)}_t\oplus z^{(\ell)}_{t+1},
\qquad
z^{(\ell)}_{t+1}\sim U_\theta(\cdot\mid x,c^{(\ell)}_t)
\]
for $t_\ell$ steps, after which a compaction transition writes the next
initial context:
\[
c^{(\ell+1)}_0\sim K_\theta\big(\cdot\mid x,c^{(\ell)}_{t_\ell}\big),
\qquad
|c^{(\ell)}_0|\leq B_0,
\qquad
|w^{(\ell)}_t|\leq B_c.
\]
The first initial context is supplied, $c^{(1)}_0=\sigma(x)$, and the
answer is read from the last iteration $L$ as
$y\sim M_\theta(\cdot\mid x,c^{(L)}_{t_L})$. The same $\theta$ runs every
iteration. The earlier paragraphs read as follows in this setting.

\emph{Stores (paragraph 12).} The initial context now has two sources:
$\sigma$ fills it in the first iteration, and the solver fills it,
through $K_\theta$, in every later one. $B_0$ therefore bounds the hint
in the first iteration and the carried state afterwards. The argument of
paragraph 14 about supplied content applies to the first iteration only,
and setting $\sigma(x)$ empty removes hints while leaving compaction
intact.

\emph{Depth and space (paragraphs 4, 13, 14).} With nonempty updates,
$t_\ell\leq B_c$, so the cap of paragraph 14 now limits one iteration,
and depth, counted over all iterations with each compaction as one
step, has no cap. Content is discarded only by compaction, so this is
the discarding machine of paragraph 12 at the granularity of
iterations: $B_0$ takes the role of the live space of paragraph 4,
holding what crosses an iteration boundary, and $B_c$ bounds the work of
one iteration. Budgeted depth (paragraph 13) is defined as before, with
traces that span iterations. A scaling statement fixes the budgets of
one iteration and describes how the depth and the number of iterations
grow with $n$.

\emph{Structure (paragraph 11).} A compaction schedule cuts an
evaluation order of $G$ into segments that each fit in one iteration.
Inside a segment every computed value stays in context. At a cut, the
values computed but still to be read must fit in $c_0$ together with the
position in the evaluation order, so at most $(B_0-O(\log n))/b$ values
cross each cut. A value that does not fit can be recomputed later from
the leaves, which stay readable in $x$, at the cost of more steps. A
trace of $d$ steps needs at least $d/(B_c+1)$ iterations.

\emph{Compaction as maintenance (paragraph 16).} $K_\theta$ is a state
maintenance task whose store is $c_0$: bounded by $B_0$ and rewritten in
full at every iteration, so anything $K_\theta$ omits is lost. A value
that waits across $r$ cuts passes through $r$ maintenance instances, and
the union bound of paragraph 16 charges each of them, so under
compaction the cost of a value grows with how long it waits. A value
written to the file of paragraph 15 is stored once, and its cost grows
with the number of entries its retrieval must search.

\emph{With a file (paragraph 15).} Compaction and the file combine: the
file holds the values, and $c_0$ holds what is needed to find them. If
the agent stores $z_v$ at an address computable from $v$, the queries of
paragraph 16 can be derived from $x$, and $c_0$ needs only the position
in the evaluation order, $O(\log n)$ bits. Budgets for one iteration
that hold one component plus $O(\log n)$ bits then suffice for instances
of every size. This is the agent that keeps notes in a file and compacts
its context.
